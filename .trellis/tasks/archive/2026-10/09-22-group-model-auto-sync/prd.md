# 分组模型自动同步开关与 claude- 前缀别名

## Goal

让分组的模型列表能按分组自行跟上上游：分组级「自动同步」开关打开后，后端周期性拉取上游模型并合并新增项；同步产生的新增模型自动获得 `claude-<模型ID>` 前缀别名，省去人工逐个补别名。同时加宽「模型与别名」抽屉，缓解三列表格的拥挤。

## 背景与现状

- 分组模型目前只有人工路径：在「模型与别名」抽屉点「同步模型」，在对话框里选同步方式、确认后点「保存修改」。上游模型更新后分组不会自己跟上。
- 新增模型的别名需要人工补。截图中的 `grok-4.7 → claude-grok-4.7` 就是手工加的，同分组其余 8 个模型没有 `claude-` 前缀别名。
- 现有「Claude 适配」开关产出的是通配别名 `claude-*[1m]`，一个分组内互斥，与本次要加的普通前缀别名是两套东西，互不干扰。

## Requirements

### R1 分组级「自动同步」开关

- 位置：「模型与别名」抽屉工具栏内，紧邻「同步模型」按钮（浏览器截图中该按钮右侧、「手动添加」左侧）。
- 形态：滑动开关（复用 `AppSwitch`），带可见文本标签，开启/关闭状态一眼可辨。
- 持久化：跟随分组保存到服务端，重启服务、更换浏览器后状态不变；默认关闭。
- 生效方式：切换开关即保存并生效，不进入抽屉的「保存修改」草稿流程，不使模型草稿变 dirty，也不因模型校验失败而回滚。
- 可见条件：与「同步模型」按钮一致，仅当该分组的 channel 支持模型发现（discovery）时显示。

### R2 后端周期性自动同步

- 参与条件：该分组开关已开启，且其 channel 支持模型发现。分组删除或开关关闭后立即退出参与。
- 行为：按固定周期（默认 1 小时，不可配置）向上游拉取模型列表，把「上游返回、分组内没有」的模型追加到该分组模型配置的末尾。
- 只增不删：上游已下线的模型不从分组里移除，交给人工用「完整同步」「仅清理」处理。禁止自动清空分组模型。
- 冲突处理：合并结果必须通过既有的模型名称/别名冲突校验。若某个新增模型会让分组产生冲突，则跳过该项，其余项照常写入；不得因个别冲突让整次同步失败，也不得写入非法状态。
- 无变化时：不产生任何写入，也不更新分组的更新时间与快照。
- 执行方式：多个分组的自动同步串行执行，单个分组的失败或超时不影响其它分组；服务停止时能及时退出，不阻塞关停。
- 失败可见性：失败只在服务端日志留痕，不改动分组模型。本次不做前端展示。

### R3 同步新增模型自动补 claude- 前缀别名

- 触发时机：所有同步动作产生的新增模型，包括后端自动同步与前端「同步模型」对话框确认后的新增项。
- 规则：新增模型自动获得别名 `claude-<模型ID>`（模型 ID 原样拼接，不截断不改写）。
- 跳过条件：模型 ID 本身已以 `claude-` 开头（大小写不敏感）时不生成；生成的别名若与分组内其它模型已认领的名称/别名冲突，则这一行不加该别名，其余行照常。
- 不追溯：同步前就已在分组内的模型不被追加别名，用户已有的别名集合不被改写。

### R4 抽屉宽度

- 「模型与别名」抽屉加宽，缓解模型 ID、别名、Claude 适配三列被挤压的问题。
- 只作用于该抽屉，不改变其它使用 `sheet` 尺寸的面板（健康详情、模型目录设置）。

## Acceptance Criteria

- [ ] AC1：支持 discovery 的分组，抽屉工具栏「同步模型」旁出现「自动同步」滑动开关；不支持 discovery 的分组不出现。
- [ ] AC2：开关默认关闭；打开后重新加载页面、重启服务，状态仍为打开；换用另一个浏览器访问同一分组，状态一致（证明落在服务端而非本地）。
- [ ] AC3：切换开关不会让抽屉的「保存修改」按钮变为可用（不进入草稿），也不会因为模型列存在校验错误而保存失败。
- [ ] AC4：开关开启的分组，在一个同步周期后，上游存在而分组内不存在的模型出现在分组模型列表中，且顺序追加在末尾；上游已下线但分组内已有的模型仍在。
- [ ] AC5：自动同步带来的新增模型带有 `claude-<模型ID>` 别名。
- [ ] AC6：手动「同步模型」对话框确认的新增模型同样带有 `claude-<模型ID>` 别名；同步前已存在的模型别名保持原样。
- [ ] AC7：模型 ID 本身以 `claude-` 开头时（如 `claude-opus-4-6`），不产生 `claude-claude-opus-4-6` 这类别名。
- [ ] AC8：某个新增模型会引入名称/别名冲突时，该项被跳过且同步整体成功，分组模型仍是通过校验的合法状态。
- [ ] AC9：关掉开关后，后续周期不再改动该分组的模型。
- [ ] AC10：自动同步失败（上游报错、超时、凭据不可用）时分组模型不变，服务日志有记录，其它分组的同步不受影响。
- [ ] AC11：「模型与别名」抽屉变宽，三列不再拥挤；健康详情与模型目录设置面板宽度不变。

## Constraints

- 前端只改 modern 入口，classic 入口不动。
- 三语（zh-CN / en-US / ja-JP）文案需同步维护，与仓库既有 i18n 约定一致。
- 不新增第三方依赖。

## Out of Scope

- 自动删除分组内已下线的模型（自动清理）。
- 分组级同步周期、同步时间窗等可配置项。
- 「上次自动同步时间 / 上次同步结果」的前端展示。
- 自动同步对模型权重、定价、启用状态等其它字段的联动。

## Notes

- 自动同步只增不删是刻意的保守选择：清空模型会让分组立刻不可用，风险远大于收益。
- 开关即时保存而非随草稿提交：模型草稿保存会因为任意一行校验失败整体失败，把开关绑在同一条通道上会被连坐。
- 开启开关后不立即触发一次同步，等下一个周期即可，避免开关切换引入额外的同步触发路径。
