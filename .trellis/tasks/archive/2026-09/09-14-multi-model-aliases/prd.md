# 分组模型支持多个别名

## Goal

把分组模型的「对外别名」从**单值替换**改为**多值追加**：一个上游模型可配置多个调用别名，且原模型 ID 始终可用；同时把别名输入从普通文本框改为标签输入（回车生成标签）。

## Requirements

### R1 多别名

每个分组模型可配置多个对外别名，上限 **10 个**。别名与模型 ID 一样对客户端可见、可路由。

### R2 原模型 ID 始终可用

映射后原模型 ID 不再失效。当前实现是「别名优先，配了别名则 ID 不可用」；改为「ID 与所有别名并列生效」。

> 这是对现有行为的**破坏性变更**：已配置别名的模型，其原 ID 从不可用变为可用。

### R3 标签输入交互

别名输入改为标签式：输入内容后**按回车生成标签**才算生效；单个输入框支持多个标签；支持删除标签与批量粘贴。

### R4 去掉启用开关

移除每行的「启用别名」checkbox。标签列表为空即「无别名」，非空即生效。消除「开关开着但别名未填」这一无效状态。

## Constraints

- **C1 存量「同 ID 多条目」必须继续可编译。** 单别名时代用户以 `{ID:"shared",Alias:"a"}` + `{ID:"shared",Alias:"b"}` 表达一个模型两个名。新规则下必须**合并**而非报错——`Compile` 失败会拖垮整个配置读取，属启动级故障。
- **C2 名称冲突必须报错。** 组内所有名称（ID + 全部别名）两两不相交；`模型A 的 ID == 模型B 的别名` 属冲突。
- **C3 响应契约与前端原子切换。** 前端 projector 是严格白名单，未知字段直接抛错，不存在双写兼容窗口；服务端与前端必须同批落地。
- **C4 不改动 en-US / ja-JP 语言包。** 它们不参与构建（见 `web/src/i18n/index.ts` 顶部注释），保持与上游同步以维持零冲突合并。

## Acceptance Criteria

- [ ] AC1 给某模型配置 2 个别名后，用 **模型 ID**、**别名1**、**别名2** 三种名称请求，均路由到同一上游模型
- [ ] AC2 别名标签可在 UI 上新增（回车）与删除，保存后刷新顺序与内容不变
- [ ] AC3 别名超过 10 个时后端拒绝并返回验证错误
- [ ] AC4 组内名称冲突（含「A 的 ID == B 的别名」）保存时被拒绝，并在正确的位置提示
- [ ] AC5 存量分组（JSON 中为旧 `alias` 单字段）加载后别名为 `[旧值]`，且原 ID 同时可用
- [ ] AC6 存量「同 ID 多条目」分组加载后名称集合正确合并，不报编译错误
- [ ] AC7 未配置别名的模型行为与改动前完全一致
- [ ] AC8 首页模型计数与访问密钥的模型过滤未因「一个模型多个名称」而虚增
- [ ] AC9 保存后落库 JSON 只含 `aliases` 字段，不再产生 `alias`
